What it is for

A single HTTP endpoint that another product's backend can call when a user asks something about health. You send the question, you get an answer in plain language and the journal articles behind it. There is no SDK to install and no model to host.

It is built for products that need to show where an answer came from: patient education, health chat, triage assistants, editorial fact checking.

How an answer is produced

  1. Retrieve. The question is matched against the journal index in both Indonesian and English, so an Indonesian question still reaches English literature.
  2. Verify. Every candidate link is resolved against the DOI registry, and titles are replaced with the registered ones. A paper whose title does not match its DOI is dropped rather than shown.
  3. Answer, or decline. The answer is written only from the selected papers, with citation markers pointing at them. If nothing relevant is found, the response says the evidence is insufficient.
  4. Fill the gap. When a topic is not represented in the index yet, the engine searches the literature for it, verifies what it finds, and answers from it in the same request.

One request

Request

# POST {{ base_url }}/api/v1/intelligence/query
{
  "query": "Is dengue spread by mosquitoes?",
  "options": { "format": "simple" }
}

Response

{
  "answer": "Dengue is transmitted by the…",
  "sources": [
    { "title": "Dengue Fever: An Overview",
      "doi": "10.5772/intechopen.92315",
      "url": "https://doi.org/…" }
  ],
  "has_evidence": true
}

Conversations stay consistent

Send your own chat room identifier and follow up questions are answered from the same papers as the first one, so the references in a thread do not change from message to message. When the user moves to a different condition, a fresh search runs and the response tells you which of the two happened.

Free while in beta

The engine is in beta and access is free of charge. Keys are issued by request so that we can keep an eye on load and talk to the people building on it.

Beta also means the honest caveats apply: the index is still growing, answers can be shallow on topics with thin literature, and the response shape may gain fields. Breaking changes will be announced to key holders before they ship, and we will give advance notice before pricing changes.
